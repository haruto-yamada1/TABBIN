# Current storage writer inventory

Issue #711 の調査時点で production code に存在する writer を、実際の
`chrome.storage.local.set` / `remove` または Chrome repository port の
`set` まで追跡した一覧です。将来設計ではなく current implementation の
制約を記録します。

Saved Tabs domain data の authoritative route は persistence control state が
1 操作につき一度だけ選択します。`legacy` route は Chrome Storage、`indexeddb`
route は Persistence v2 の transaction を使い、別 route への fallback や dual
write は行いません。`userSettings` など domain 外の設定は引き続き Chrome
Storage が source of truth です。

## Queue, barrier, and notification boundaries

- `urlRecordMutationQueue`, `savedTabsStorageMutationQueue`,
  `autoCategorizeTabsQueue`, `saveUrlsToCustomProjectsQueue`, and
  `addUrlIdToDomainModeQueue` are module-local Promise queues. They serialize only
  callers sharing one loaded module instance. They do not coordinate another
  extension context and disappear on page or service-worker restart.
- `migrateDomainStorageToHostname` alone attempts a cross-context Web Lock. If
  Web Locks is unavailable it runs without that lock. The other migrations use
  module booleans or persistent completion flags, but do not block normal
  writers between their reads and writes.
- Every migrated-domain read/write now enters the #727 shared Web Lock. #738
  acquires the same lock exclusively while taking each raw snapshot and source
  fingerprint. Pure analysis runs outside the lock, followed by an exclusive
  re-read; a mismatch is persisted as `stale`. A later status read repeats the
  fingerprint comparison, so a normal write after a healthy preflight also
  invalidates approval without observing raw user content.
- `chrome.storage.local` writes emit `chrome.storage.onChanged`. Saved Tabs UI
  adapts changes for its watched keys and `ThemeProvider` watches its theme key,
  but most writers do not wait for consumer acknowledgement. At this snapshot,
  each URL module context lazily subscribes when `storage.onChanged` is
  available. An own `urls` change in the `local` area invalidates that context's
  `urlRecordsCache`; without the API, reads bypass the cache. This is cache
  coherence only: an in-flight read caches its snapshot only if the cache
  generation and event API identity remain unchanged. API transitions detach
  the prior listener when supported and invalidate the cache. This is not
  transactional RMW or cross-context write serialization. #739 implements the
  v2 boundary as a post-commit, revisioned scope event over `PersistenceChangePort`.
  The event contains invalidation metadata only; consumers re-run their current
  consistent Query and never treat the event as cache data. Settings remain on
  a settings-specific `chrome.storage.local` control-plane change path and are
  not a persistence-change scope. The authoritative protocol is
  [`persistence-change-invalidation.md`](persistence-change-invalidation.md).

### Issue #727 enforced production paths

Every path below reaches a route-aware app-composition data plane or an
IndexedDB adapter with an injected `PersistenceOperationGatePort`. The router
selects one route per operation. The legacy facade holds a shared barrier for
each Chrome Storage operation; the IndexedDB adapter holds it for the complete
snapshot, revision, or commit operation.
Chrome domain repository constructors require an explicitly injected port and
have no raw-storage default, so a new composition caller cannot bypass the gate
by omitting an argument.

| Required path                  | Enforced surface                                                                                                   |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------ |
| URL save / delete              | `backgroundSavedTabsDataPlane.ts` and route-aware Saved Tabs use cases                                             |
| saved-tabs query               | route-aware Saved Tabs composition and `IndexedDbPersistenceSnapshotReader`                                        |
| collection mutation            | route-aware Saved Tabs composition and `IndexedDbPersistenceUnitOfWork`                                            |
| options import/export read     | `src/features/options/lib/import-export/flows.ts` and the Persistence v2 backup compositions                       |
| analytics query                | `loadAnalyticsRecords.ts`, `analyticsRoute.helpers.ts`, and `AnalyticsRoute.tsx` through the background data plane |
| AI saved URL context build     | `src/lib/background/ai-chat.ts` through the background data plane                                                  |
| expiration / cleanup job       | `src/lib/background/expired-tabs.ts` through the background data plane                                             |
| context menu save              | `extension-actions.ts` through the background data plane                                                           |
| background tab created handler | `src/lib/background/url-storage.ts` through the background data plane                                              |

The direct control-state repository and #738's raw reader/preflight repository
are the raw local-storage exceptions inside migration/control plumbing; they
must not call the gated facade recursively. Raw source snapshot/recheck and
preflight record writes run while the shared #727 coordination adapter holds
the exclusive lock. Control/preflight record reads may run outside that lock
because they contain no user data. Settings, UI theme, and release
display controls remain outside the migrated domain-data route. In particular,
both `createSavedTabsRepositories` and `createSavedTabsUseCasesDeps` inject the
gated domain port into domain repositories and a separate raw settings port
into `UserSettingsRepository`, so an `indexeddb` cutover cannot turn a settings
read into a legacy route mismatch.

The recovery notice's emergency backup action calls #738's raw reader under the
same exclusive coordination boundary. Its “Run checks and retry” action writes
only the aggregate preflight control record, then invokes bootstrap retry after
a healthy result; it does not mutate legacy source records.

Production-equivalent background URL mutation and Options export tests execute
their real call paths and assert that `PersistenceBootstrap.ready()` precedes
the first raw domain storage read.

## Barrier participation matrix

| Writer family                                  | #738 read-only preflight                                   | #727 migration readiness | Current coordination                           |
| ---------------------------------------------- | ---------------------------------------------------------- | ------------------------ | ---------------------------------------------- |
| Normal UI/application/repository writers       | Exclusive snapshot/recheck; later writes make status stale | Shared ready gate        | Stable cross-context Web Lock                  |
| Background listeners and scheduled maintenance | Exclusive snapshot/recheck; later writes make status stale | Shared ready gate        | Stable cross-context Web Lock                  |
| Import/restore and undo                        | Normal writes invalidate #738 fingerprints                 | Shared ready gate        | Stable cross-context Web Lock per storage call |
| URL migration                                  | Must not be called by preflight                            | Shared legacy-route gate | Module flag is optimization only               |
| Parent-category migration                      | Must not be called by preflight                            | Shared legacy-route gate | Stable cross-context Web Lock                  |
| Hostname migration                             | Must not be called by preflight                            | Shared legacy-route gate | No unlocked fallback                           |
| URL storage readers/writers                    | Normal writes invalidate #738 fingerprints                 | Shared ready gate        | Local cache plus cross-context barrier         |

The direct consequence is that current correctness is not restart-dependent only
where storage is re-read on entry. Module booleans, caches, Promise queues, and
drag state are optimizations or transient workflow state, not durable concurrency
control. #727 places every inventoried domain read/write behind
`PersistenceBootstrap`; #738 takes a raw non-repairing snapshot and versioned
SHA-256 fingerprint while that barrier is exclusive, releases it for pure
identity/relation/integrity/capacity analysis, then re-acquires it to re-read and
persist `healthy`, `blocked`, or `stale` under
`tabbin:migrationPreflight:v1`. #728 performs bounded strict-durability target
transactions under one exclusive lifecycle, then verifies the complete
read-back before publication. The lifecycle compares #738's approved and
current source fingerprints before writes and again before verification.
A mismatch fails closed; a subsequent preflight status read records the changed
source as `stale`.

## Handoffs

- #726 replaces domain blob writers with IndexedDB repositories and
  use-case-sized multi-store transactions.
- #727 provides a single migration-readiness gate for every domain read/write,
  including background and scheduled paths.
- #728 owns raw legacy parsing, pure conversion, transactional migration,
  read-back, and integrity verification.
- #738 implements read-only preflight and source-fingerprint invalidation. Its
  raw reader does not call the repairing getters listed above, and its separate
  control record contains aggregate diagnostics only.
- #739 replaces key-specific `chrome.storage.onChanged` expectations for v2
  domain data with a commit-after-transaction change notification and re-query
  protocol. Settings retain their settings-specific control-plane change path
  and have no `PersistenceChangeScope`.
