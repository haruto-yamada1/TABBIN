# Current storage writer inventory

Issue #711 の調査時点で production code に存在する writer を、実際の
`chrome.storage.local.set` / `remove` または Chrome repository port の
`set` まで追跡した一覧です。将来設計ではなく current implementation の
制約を記録します。

現状は単一の authoritative writer を持ちません。同じ key を Saved Tabs page、
Options、Analytics、AI、background service worker から書きます。
`chrome.storage.local.set` の 1 呼び出しは一括で反映されますが、先行する
`get` と合わせた read-modify-write は transaction ではありません。

## Required storage keys

This section lists the keys required by the Issue #711 contract. Auxiliary,
support, migration-control, and UI-control keys are recorded in the applicable
writer rows below rather than treated as primary domain keys.

- `savedTabs`
- `urls`
- `customProjects`
- `parentCategories`
- `userSettings`
- `aiChatConversations`
- `savedAnalyticsViews`

## Writer categories

- explicit mutation

- normalize-on-read

## Queue, barrier, and notification boundaries

- `urlRecordMutationQueue`, `savedTabsStorageMutationQueue`,
  `autoCategorizeTabsQueue`, `saveUrlsToCustomProjectsQueue`, and
  `addUrlIdToDomainModeQueue` are module-local Promise queues. They serialize only
  callers sharing one loaded module instance. They do not coordinate another
  extension context and disappear on page or service-worker restart.
- `migrateDomainStorageToHostname` alone attempts a cross-context Web Lock. If
  Web Locks is unavailable it runs without that lock. The other migrations use
  module booleans or persistent completion flags, but do not block normal
  writers between their reads and writes.
- No current normal writer participates in the read-only preflight barrier from
  #738 or the migration-readiness barrier from #727. A normal write after a
  preflight does not currently invalidate a source fingerprint. #738 must use a
  raw, non-repairing reader and must treat this limitation as a stale-preflight
  risk.
- `chrome.storage.local` writes emit `chrome.storage.onChanged`. Saved Tabs UI
  adapts changes for its watched keys and `ThemeProvider` watches its theme key,
  but most writers do not wait for consumer acknowledgement. At this snapshot,
  `urlRecordsCache` is invalidated by writers in its own module and explicit
  callers only; it has no general `storage.onChanged` listener, so another
  context can leave the cache stale. #739 owns the v2 notification protocol.

## Barrier participation matrix

| Writer family                                  | #738 read-only preflight                   | #727 migration readiness | Current coordination                           |
| ---------------------------------------------- | ------------------------------------------ | ------------------------ | ---------------------------------------------- |
| Normal UI/application/repository writers       | No participation                           | No participation         | Some module-local queues only                  |
| Background listeners and scheduled maintenance | No participation                           | No participation         | Service-worker instance state only             |
| Import/restore and undo                        | No participation; can stale a prior result | No participation         | Snapshot restore or several independent writes |
| URL migration                                  | Must not be called by preflight            | No shared ready gate     | Module boolean and completion flag             |
| Parent-category migration                      | Must not be called by preflight            | No shared ready gate     | No cross-context lock                          |
| Hostname migration                             | Must not be called by preflight            | No shared ready gate     | Web Lock when available; unlocked fallback     |

The direct consequence is that current correctness is not restart-dependent only
where storage is re-read on entry. Module booleans, caches, Promise queues, and
drag state are optimizations or transient workflow state, not durable concurrency
control. #727 must place every domain read/write behind `PersistenceBootstrap`,
#728 must perform migration as one verified transaction, and #738 must invalidate
preflight by source fingerprint once normal writes are observable.
