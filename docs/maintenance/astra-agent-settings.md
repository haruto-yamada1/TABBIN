# TABBIN の Astra 向けエージェント設定

確認日: 2026-09-13。対象は TABBIN 内のエージェント資産。
個人の Codex 設定、モデル選択、sandbox・認証設定は変更していない。

## 根拠と判断

[投稿1と添付の監査指示書](https://x.com/Gencoin8/status/2096819118595084431)
および[投稿2の運用記事](https://x.com/Gencoin8/status/2095736742586581480)を確認した。
添付指示書の6観点は監査の補助として用い、投稿の設定例をそのまま実行していない。

OpenAI は、Astra が skill や AGENTS.md の指示に強く反応することを踏まえ、
指示の監査、自律的な継続、委任条件、検証量、文章の書き方を調整するよう案内している。
今回の変更はこの方針を TABBIN の既存契約に合わせたもの。
性能向上率やコスト削減率は測定していない。
[公式 Astra prompting guide](https://developers.openai.com/api/docs/guides/latest-model/gpt-6-astra.md#prompting-best-practices)

## 監査結果と変更

`.apm/skills/` の50件の入口を監査し、問題がある手順の参照資料も確認した。
14件のskillを調整し、残りは必要なプロジェクト契約や用途別手順として維持した。
`.apm/instructions/` の原本を変更し、APM で各クライアント向けに生成する。

| 観点         | 確認した問題                                                              | 対応                                                                    |
| ------------ | ------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| 広い発火条件 | 設計済みの小変更への brainstorming、一般的な簡潔さの依頼で caveman が発火 | 未決定の設計と明示的なモード依頼に限定                                  |
| 入口の情報量 | TDD・検証・完了手順の一般論と重複、create-skill の長い説明                | 判断と契約を残して入口を短縮し、既存の詳細資料へ必要時に参照            |
| 固定手順     | 3タスクごとの待機、失敗回数による原因断定                                 | 依存関係・証拠・指定されたレビュー境界で進行を判断                      |
| 文脈の取得   | リファレンス全文の強制、plan全文の委任                                    | 関連経路・契約から調査し、担当範囲と参照先を委任                        |
| 検証の重複   | 回答ごとのFULL再実行、coverage 100%固定、全skill個別のpressure評価        | 現在の差分に対応する証拠を再利用。設定されたthresholdと変更別検証を使用 |
| 不要な確認   | 既に実装・PRを依頼されても設計承認や4択を要求                             | 許可済み範囲を継続し、結果や許可を変える未決定事項だけ確認              |

レビュー依頼とサブエージェント実装の手順も、既存のリスク表に統一した。
委任先への無条件commit指示を除き、担当ファイルの分離と他者変更の保全を明記した。

編集時の formatter hook は、設定で除外されたファイルへの oxfmt の「対象なし」を
整形違反として報告していた。既存の終了時hookと同じオプションで除外設定を尊重し、
実際の未整形ファイルや formatter 実行失敗は引き続き拒否する。
実hook・実oxfmtによる6ケースで、修正前の3失敗と修正後の6成功を確認した。

## 維持する契約

- コード変更の `bun run quality:check`、必要な `bun run test:coverage`。
- coverage threshold の原本は `vitest.ci.config.ts`。しきい値を下げない。
- 本番に近い回帰再現と、保存・権限・ユーザーデータ境界の検証。
- commit / push / PR / Issue / merge 等の操作別の許可境界。
- fail-closed、既存変更の保全、`.apm` 原本と生成先の同期。
- context-mode / RTK のログ処理・ツール境界。これは実行環境の制約として維持する。

create-rule は、旧版のシナリオでも既存設定から範囲を判断できたが、
「必須の質問」という逆向きの指示を整理して解釈を統一した。
worktree の既定場所、通常のテスト失敗への対応、未依頼のcommitも同じ方針で揃えた。
個人領域や外部配布の同名skillはこの変更の対象外。

## 検証

旧版・新版の判断シナリオを独立エージェントで比較する。
これは指示を読んだ判断の評価であり、実タスクの速度・成功率のベンチマークではない。
実行記録はハーネス `astra-agent-optimization-20260912` に残す。

- 既存の agent-contract / skill-reference-integrity / sync-agent-config テスト。
- `bun run apm:sync` と `bun run apm:check` による生成・冪等性・一致の検査。
- `bun run quality:check` とハーネスの検証・独立評価。

実行結果:

- 関連する既存テスト: 3ファイル・67件成功。
- formatter hook回帰: 修正前3失敗、修正後6件成功。
- `quality:check`: 終了コード0。全427ファイル、4,613件成功・1件skip。
- `test:coverage`: 終了コード0。statements 93.96%、branches 87.00%、functions 92.89%、lines 93.94%。設定済みglobal / per-glob thresholdを通過。
- `apm:sync` / `apm:check`: ともに終了コード0。変更したskillの原本・配布先一致、参照切れ0。
- 旧新版の判断比較: A〜Lの入力と結果をハーネスの `policy-scenarios.md` に記録。
- 独立Evaluator: `approved`、追加指摘なし。`harness:validate` 通過。

最初の品質チェックはsandbox内のlocalhostポート制限でKnipが停止した。
ポート利用可能な経路で同じ全体コマンドを再実行し、最後まで通過した。

全体surface監査には既存の警告が残る。固定コードの `node -e` と、
「そのまま実行しない」という安全指示への機械的な検知、以前から存在する
APM管理外のCursor用skill 9件が対象で、今回の変更による退行ではないことを
独立評価で確認した。監査ロジックの否定表現への対応とCursor資産の整理は、
別途検討できるfollow-up候補とし、警告を隠す変更や既存資産の削除は行っていない。
