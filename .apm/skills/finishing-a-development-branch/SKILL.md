# 開発ブランチの完了

まず会話で依頼された操作を確認する。許可条件は
`.apm/instructions/repository-guidelines.instructions.md` の
「Commit / Push / PR 許可境界」に従う。
依頼済みの操作について、定型の4択や再承認を求めない。

## 検証と対象

- 現在の差分に対する必須ゲートの結果を確認する。差分や環境が変わっていなければ、成功済みの検証を再実行しない。
- 未検証や失敗があれば、必要な検証・原因調査・修正を行ってから完了を報告する。
- 作業ブランチ、working tree、remote、PR の有無を確認する。他者変更をstageしない。
- base はユーザー指定または既存 PR を優先し、TABBIN の通常 PR は `develop` を使う。推測で main/master に統合しない。

## 依頼ごとの処理

| 依頼               | 処理                                                                                     |
| ------------------ | ---------------------------------------------------------------------------------------- |
| ローカル修正のみ   | 差分・検証結果・残る問題を報告し、ブランチと worktree を保持する。                       |
| commit / push / PR | 許可された操作だけ $commit-push-pr で完了する。PR 作成後も worktree を保持する。         |
| merge              | 個別の明示依頼がある場合だけ対象と方式を確認して実行し、統合結果を検証する。             |
| 破棄 / cleanup     | 対象のブランチ・worktree・未保存差分・未公開commitを確認し、依頼された範囲だけ処理する。 |

統合方法の相談だけなら、状況に合う選択肢と推奨を示す。
未依頼の公開、merge、破棄、force-push を完了手順に含めない。
破棄範囲が曖昧な場合は、失われる内容を示して確認する。
未コミット差分や他者の作業を暗黙に削除しない。
