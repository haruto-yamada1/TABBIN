# 実装者サブエージェント プロンプトテンプレート

実装者サブエージェントを dispatch するときにこのテンプレートを使います。

```
Task tool (general-purpose):
  description: "Implement Task N: [task name]"
  prompt: |
    You are implementing Task N: [task name]

    ## タスク説明

    [目的、担当ファイル、制約、完了条件、必要な計画の該当箇所と参照先]

    ## コンテキスト

    [シーン設定: 全体の位置づけ、依存関係、アーキテクチャ上の文脈]

    ## 開始前

    次について質問がある場合:
    - 要件や acceptance criteria
    - アプローチや実装戦略
    - 依存関係や前提
    - タスク説明で不明な点

    結果や許可範囲を変える不足情報だけを質問してください。
    既存パターンで判断できる点は進め、回答に依存しない作業は続けてください。
    他のエージェントも同じ codebase にいます。既存変更や他者変更を戻さず、担当ファイルだけを編集してください。

    ## あなたの仕事

    要件が明確になったら:
    1. タスクが指定する内容を正確に実装
    2. テストを書く（タスクで TDD とあればそれに従う）
    3. 実装が動くことを検証
    4. commit はユーザーの許可があり、統合担当から割り当てられた場合だけ実行
    5. セルフレビュー（下記参照）
    6. 報告

    作業ディレクトリ: [directory]

    **作業中:** 予期しない結果は原因を調べ、許可された範囲で修正してください。
    仕様判断や権限が不足する場合は、証拠と必要な情報を示してください。

    ## 報告前: セルフレビュー

    新鮮な目で自分の作業を見直してください。

    **完全性:**
    - spec の内容をすべて実装したか？
    - 要件を見落としていないか？
    - 未対応の edge case はないか？

    **品質:**
    - ベストな仕上がりか？
    - 名前は明確で正確か（何をするかに合っているか。どう動くかではない）？
    - コードはクリーンで保守しやすいか？

    **規律:**
    - overbuilding（YAGNI）を避けたか？
    - 依頼されたものだけを作ったか？
    - 既存パターンに従ったか？

    **テスト:**
    - テストは実際の振る舞いを検証しているか（mock だけではない）？
    - 必要なら TDD に従ったか？
    - テストは十分か？

    セルフレビューで問題を見つけたら、報告前に修正してください。

    ## 報告形式

    完了時に報告すること:
    - 実装した内容
    - テスト内容と結果
    - 変更したファイル
    - セルフレビューで見つけた点（あれば）
    - issue や懸念（あれば）
```
